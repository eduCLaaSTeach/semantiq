# Phase Planning Outputs

Generated by `/generate-phase-plan` from two live sources:
1. approved active requirements under `/doc/solutiondocument/`;
2. the repository's current Claude standards loaded through root `CLAUDE.md` and task-gated `.claude` settings.

Expected outputs:
- `PROJECT_STANDARDS_BASELINE.md` - snapshot of standards/gates used for this planning run.
- `00_Solution_Understanding.md`
- `01_Requirement_Register.md`
- `02_Gap_Conflict_Report.md` - the open findings.
- `03_Architecture_Overview.md`
- `04_Dependency_Map.md`
- `05_Planning_QA_Report.md`
- `MASTER_PHASE_PLAN.md`
- `phases/PHASE_0X_<name>.md` - one per macro phase, at most five.

## The Five Macro Phases
A plan has no more than five macro phases, with IDs `P01` to `P05`:
1. Phase 1 - Platform, Infrastructure & Master Foundation
2. Phase 2 - Core Application, Login, Administration & AI Foundation
3. Phase 3 - Feature / Function Design & Dependency Approval
4. Phase 4 - Feature / Function Build & Technical Verification
5. Phase 5 - UAT, Acceptance & Release Readiness

A smaller solution uses fewer phases only where a phase is genuinely not applicable, never more. Detailed feature work belongs in tasks and subtasks, not in additional phases.

In Phase 2, login follows the application's authentication model as recorded in `.claude/PROJECT-CONTEXT.md`. Authorization is the application's own per-feature authorization, and the AI foundation is the AI model catalog per `.claude/rules/ai-model-catalog.md`, with its guardrails, kill switches, and limits per `.claude/rules/ai-guardrails.md`.

Complete feature and requirement coverage is also reflected in `/doc/corerepo/`, in `03_FEATURE_FUNCTION_INDEX.md` and `04_REQUIREMENT_COVERAGE.md`.

The standards baseline is not itself authoritative. The live repository standards remain authoritative and must be re-checked when plans/tasks are refreshed.

Implementation is blocked until a human explicitly approves `02_Gap_Conflict_Report.md` and `MASTER_PHASE_PLAN.md`. Who approved each and when is recorded in the Solution Planning And Task Tracking section of `.claude/PROJECT-CONTEXT.md`; a status line inside the document is not approval.
