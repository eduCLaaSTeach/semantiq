# Data Context Register

Every production entity has a named owner, classification, residency and retention before go-live.

The control plane runs on cPanel MySQL. **Its hosting geography is unconfirmed** and is carried as an open item rather than assumed.

| Data ID | Entity / fields | Source & owner | Purpose | Classification / personal | Storage | Retention | Access | Validation | Status |
|---|---|---|---|---|---|---|---|---|---|
| DATA-001 | `users` (name, email, `entra_object_id`, `entra_tenant_id`) | Microsoft Entra ID / customer directory owner | Local mirror of a directory account, so authorisation and audit have something to attach to | Confidential / Yes: name, work email, directory object id | Control plane | Removed when the directory account is deprovisioned | Administrator and above | VAL-AUTH-STATE-001 | Implemented |
| DATA-002 | `users.password` | SemantIQ | Fallback for accounts the directory does not hold | Restricted / No | Control plane, hashed | With the account | Never read back | VAL-AUTH-PAIR-001 | Implemented |
| DATA-003 | `users.role` | SemantIQ / Administrator | The platform authority tier | Internal / No | Control plane | With the account | Administrator and above | VAL-NAV-POLICY-001 | Implemented |
| DATA-004 | `users.is_auditor` | SemantIQ / System Administrator | Compliance-evidence access without an operational tier | Internal / No | Control plane | With the account | System Administrator | VAL-NAV-AUDITOR-001 | Implemented |
| DATA-005 | `domain_entitlements` (domain, scope, granted_by) | SemantIQ / Administrator | Which business domains an account may see. The second access dimension | Internal / No | Control plane | Retained as a permission-change record | Administrator and above | VAL-NAV-DOMAIN-001 | Implemented |
| DATA-006 | `sessions` | Laravel | Signed-in session state | Confidential / Yes: user id, IP | Control plane | Cleared on expiry or sign-out | None, framework internal | None | Implemented |
| DATA-007 | Business metrics, KPIs, insights | Customer Fabric estate | The intelligence the product exists to deliver | Confidential to Restricted by domain | Customer OneLake, NOT the control plane | Customer policy | Domain entitlement plus row, object and field security | VAL-SOV-GEO-001 | Not implemented. No data source exists in this phase |
| DATA-008 | `organisations` (code, name, status, version) | SemantIQ installer, then the customer via ADM-002 | The customer organisation that owns this instance. The anchor every scoped record points at | Internal / No | Control plane | For the life of the instance | System Administrator to change; every scoped read depends on it | VAL-ORG-CODE-001, VAL-ORG-CONTEXT-001 | Implemented, one bootstrap row |
| DATA-009 | `audit_events` (occurred_at, actor, action, module, resource, outcome, redacted summaries, reason, ip, correlation id, environment) | SemantIQ | The append-only record of who changed what | Internal / **Yes: actor identity and IP address** | Control plane | Seven years, project policy baseline, not a constant. No application delete path exists | System Administrator to read. No update or delete path at all | VAL-AUDIT-REDACT-001 | Implemented |
| DATA-010 | `audit_events.before_summary` / `after_summary` | SemantIQ | What changed, without the value that changed | Internal / No | Control plane | With the row | System Administrator | VAL-AUDIT-REDACT-001 | Implemented. **A secret-bearing key stores a placeholder; a long value stores a truncated SHA-256, never the value** |
| DATA-011 | `system_settings` (key, value, updated_by) | SemantIQ / System Administrator | Runtime configuration overrides. The catalogue and every default live in code | Internal / No | Control plane | Until changed. Every change is audited | System Administrator | VAL-SET-KNOWN-001, VAL-SET-NOSECRET-001 | Implemented. **No secret may be stored here and the writer refuses one** |
| DATA-012 | `feature_flags` (key, enabled, reason, updated_by) | SemantIQ / System Administrator | Which optional capabilities are switched on | Internal / No | Control plane | Until changed. Every change is audited | System Administrator | VAL-FLAG-KNOWN-001, VAL-FLAG-PRECOND-001 | Implemented |
| DATA-013 | `organisations` profile fields (legal name, registration number, country, domain, time zone, currency, contacts) | Customer via ADM-002 | The organisation's own identity and policy context | Internal / Contacts are a name or role, never a credential | Control plane | Life of the instance | `admin.organisation.*` | Organisation profile rules | Implemented |
| DATA-014 | `business_units`, `teams` | Customer via ADM-003, ADM-004 | Organisational structure, used as a SCOPE. Grants nothing | Internal / No | Control plane | Retained; disabled rather than deleted so history stays auditable | `admin.business_units.*`, `admin.teams.*` | VAL-BU-LOOP-001, VAL-BU-CODE-001, VAL-TEAM-BU-001 | Implemented |
| DATA-015 | `roles`, `role_permissions` | SemantIQ built-ins plus customer-defined | Reusable authority profiles and the permission keys they carry. **No `permissions` table: the catalogue is code** | Internal / No | Control plane | Retained; versioned so a review can record which version it approved | `admin.roles.*` | VAL-ROLE-SYSTEM-001, VAL-ROLE-ASSIGNED-001, VAL-PERM-DENY-001 | Implemented |
| DATA-016 | `user_roles` | SemantIQ / Administrator | Additional roles held by an account, additive within the primary tier's ceiling | Internal / No | Control plane | Retained as a permission-change record | `admin.roles.assign` | VAL-USER-ELEVATE-001 | Implemented |
| DATA-017 | `users` identity context (`organisation_id`, `business_unit_id`, `team_id`, `user_type`, `status`, `authentication_source`, `external_reference_id`, `access_start`, `access_end`) | Customer via ADM-005 | Where an account sits, whether it may sign in, and for how long | Confidential / Yes: employee reference is customer-supplied personal data | Control plane | With the account | `admin.users.*` | VAL-USER-EMAIL-001, VAL-USER-DISABLED-001, VAL-USER-WINDOW-001, VAL-USER-LASTADMIN-001 | Implemented |
| DATA-018 | `access_reviews`, `access_review_items` | SemantIQ / Administrator | Evidence that access was checked and what was decided. Items carry a LABEL snapshot so the evidence survives a later rename or revocation | Internal / Yes: names the accounts reviewed | Control plane | Retained as compliance evidence. Seven years is the project baseline | `admin.access_reviews.*` | None | Implemented |
