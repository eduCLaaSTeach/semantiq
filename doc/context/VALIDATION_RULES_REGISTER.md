# Validation Rules Register

Validation rules are canonical server-side rules. Client-side validation may improve UX but must not be the only enforcement for security, data-integrity, tenant, permission or sovereignty rules.

| Validation ID | Entity/field/action | Rule | Severity | Server enforcement | Client UX | Error/help message | Source requirement | Test IDs | Data/security/sovereignty relevance | Status |
|---|---|---|---|---|---|---|---|---|---|---|
| VAL-CORE-TENANT-001 | Organisation tenant ID | Authenticated tenant must match onboarded tenant for privileged actions | Block | Required | Show mismatch | Tenant does not match this organisation | FR-AUTH-002 | TBD | Tenant isolation | Planned (Phase 01) |
| VAL-CORE-ORG-001 | Every customer-owned entity | A query may reach only rows belonging to the active organisation. No active organisation means no rows, never all rows | Block | Required (global Eloquent scope, fails closed) | Not surfaced; the record is simply absent | Not found | NFR-SEC-02 | `OrganisationBoundaryTest`, `ConfigurationModelBoundaryTest` | Tenant isolation. A failure here is a release blocker under the sovereignty standard section 9 | Implemented |
| VAL-AUTH-STATE-001 | Sign-in callback state and nonce | The `state` must match the session value and be single use; the ID token `nonce` must match | Block | Required | Generic sign-in failure | Sign-in could not be completed | FR-AUTH-001 | `tests/Feature/Auth/SignInTest.php` | CSRF and replay protection on the identity flow | Implemented |
| VAL-NAV-POLICY-001 | Navigation node access policy | A node names a policy; an unknown policy denies rather than allows | Block | Required | The node is not rendered | Not applicable | NFR-SEC-02 | `tests/Feature/Shell/NavigationTest.php` | Fail-closed authorisation on the shell | Implemented |
