SemantIQ · Administrator Foundation Release 1

What you are actually building

One release, seven gates, five config files that are yours. Everything else is scaffolding you can ignore.

SemantIQ is two products in one application. Business people get Decision Intelligence — Sales, Finance, Ask SemantIQ — and never learn the word “Fabric”. Administrators get a control plane that automates Microsoft Fabric on their behalf.

This release is the control plane’s backbone. It is not the product a customer logs in to use. It is the plumbing everything else stands on: who can sign in, who may do what, what gets recorded, and what data you hold and where it lives.

The part that is confusing you

Fifteen config files. Five are yours.

The other ten ship with every Laravel application and have barely been touched. You never need to open them.

Yours — these hold real decisions

5 files
  • navigation.php The whole menu tree. By far the biggest file, and it is a list, not logic.
  • security.php Sign-in mode, session rules, API controls. Gate 3.
  • governance.php Retention categories, exception types, audit log views. Gate 4.
  • platform.php The system settings catalogue. Gate 1.
  • brand.php Essentially one line: where the approved logo pack lives.

Stock Laravel — ignore

10 files
app · auth · cache · database · filesystems · logging · mail · queue · services · session

Why permissions live in a config file rather than a database table. A database row can be edited quietly by anyone with access. A config file cannot — changing it means opening a pull request where a human can see exactly which privilege moved and why.

That is the trade you made: these files exist so that no one, including us, can grant themselves a permission without leaving a reviewable trace.

Before Gate 4 can close

Four things still open

Append-only triggers on privacy correction notes. This one formally blocks Gate 4. A correction note records what a person disputed about their own data — if it can be edited afterwards, the party being disputed can rewrite the dispute. Lands in R1.4c.

R1.4c itself. Privacy requests, breach register, and the governance overview that summarises everything the earlier batches built.

AI processing geography reads “Not determined”. Correct behaviour, not a bug — SemantIQ will not invent a sovereignty position. But it is a question only you can answer, and cross-border AI stays switched off until you do.

No retention period is set for any of the seven data categories. Also deliberate: how long to keep personal data is a legal judgement, not something software should guess. The screen says Not Configured rather than showing a reassuring default nobody agreed to.
