## Scope and conventions

Each row is one end-to-end business flow. Features (Bolts) are grouped under the Feature
Cluster (Story) they belong to, matching the clusters used in documents 01 and 02.

**On AI and automation.** This platform's purpose is to build an AI application, so the
distinction matters more here than usual and is applied strictly:

- **Rules-based automation** covers everything deterministic — provisioning, verification
  probes, scheduling, retries, threshold checks, comparisons, gate enforcement. The great
  majority of SemantIQ's own behaviour is this.
- **AI-assisted** covers only where a model generates or suggests. Every such point states
  its mandatory human review step.
- **AI absent by design** is stated explicitly where a reader might expect AI and it is
  deliberately excluded.

**A standing rule across every workflow:** SemantIQ never has a model decide a business
definition, approve an answer, grant access, or pass a gate. Those are human decisions with
named owners, and the platform's job is to make sure they were actually made.

## Cross-workflow notes

### Where AI is used, and where it deliberately is not

| AI is used for | AI is deliberately not used for |
|---|---|
| Drafting object descriptions from structure and lineage | Deciding a business definition |
| Extracting candidate synonyms from real failed questions | Applying a synonym or rename without review |
| Suggesting entity groupings and cross-source field mappings | Confirming a mapping — a business owner does that |
| Proposing an ingestion method from source characteristics | Selecting it — the Data Engineer accepts or overrides |
| Drafting agent instructions, source descriptions and routing descriptions | Publishing them unread |
| Grouping failed questions by pattern | Auto-applying a fix from a conversation log |
| Proposing a failure-cause classification | Confirming the cause or the remediation |
| The Data Agent and Copilot Studio agent answering user questions — the product itself | Establishing a ground-truth expected answer, which would make measurement circular |
| — | Approving an answer, granting access, passing a gate, promoting a change, or scoring go-live readiness |

**The pattern is consistent:** AI drafts and suggests; humans decide and approve; automation
enforces and verifies. Every gate in this platform is passed by a named person against
evidence the platform assembled.

### Exception handling common to every workflow

- A transient integration failure retries with exponential backoff and jitter within its
  configured limit; a permission or configuration failure halts immediately with the
  underlying platform error surfaced rather than paraphrased.
- A failure halts only its own dependency branch. Independent work continues.
- Every operation is idempotent, so a resumed workflow never duplicates an artifact in the
  customer's tenant.
- Where a required verification cannot be performed, the only route forward is a written
  exception approved by a named person and carried into the go-live readiness view.
- Every workflow transition is recorded with actor, target, correlation identifier and
  outcome.
