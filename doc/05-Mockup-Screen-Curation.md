## 1. There is no visual direction to choose

The look and feel is already approved. This document curates **which approved archetype and
components each screen uses, and why** — it does not propose a style, a palette, a font or a
layout. The accompanying HTML mockup is built as a real instance of the approved design
system in both themes, not as a placeholder theme to be re-skinned.

**Outstanding asset:** the approved per-theme wordmark, the C2S short mark and the favicons.
The mockup carries a clearly marked placeholder in the sidebar brand block and flags it in
the file. Please supply the asset pack and its installed location.

## 3. Interactive mockup

**File:** `doc/mockups/semantiq-shell-mockup.html` — self-contained, no external dependencies
beyond the approved Google Fonts import.

**What it renders:**

- The full approved shell: full-height rail owning the top-left corner, top bar over the
  canvas only, visible dividers between all three regions, 52px rail head matched to the top
  bar so their bottom dividers form one continuous line, pinned brand block as the only
  collapse control with just the nav list scrolling, collapsible rail persisting its state,
  and legible flyouts when collapsed.
- The complete navigation tree from 04-UI-Specification section 4, across all four clusters
  at their real depth.
- Both themes, with the System / Dark / Light segmented control in the profile menu's fixed
  Appearance section, System by default and persisted.
- Four screens in full: **Blueprint Runner**, **Enrichment Queue**, **Test Console** and
  **Assistant**.
- The real states, not only the happy path: the loading skeleton, both empty flavours and

**Known placeholder:** the brand assets. The mockup carries a marked placeholder in the
brand block and an HTML comment naming the missing asset. **Impact:** the sidebar brand block

## 4. Final reporting

**Archetypes and deciding factors.** Dashboard where the user scans for exceptions
(Dashboard, Readiness). List / index where the user searches (Projects, Enrichment Queue,
Ground Truth). Builder where parts compose behind a gated advance (Blueprint Runner, Agent
Builder). Detail / show where one record is read and acted on (Step Detail, Agent Publication
Gate, Go-Live Readiness) and for the two conversational surfaces per the named conflict.
Form for data entry (Object Enrichment). Settings / config for the test-before-save contract
(Connection Configuration). Runners-up were recorded and rejected with their reason on four
screens.

**Shell placement.** All four fixed clusters in their fixed order, none added, renamed or
reordered. Deepest path is three levels (`Data Platform` → `Ingestion` → `Pipelines`). No
fourth accordion level. The only tab strip is the project record's facets, which is
record-facet handling and is terminal. Standing navigation stayed in the sidebar throughout;
the top bar carries no navigation, no global search and no action buttons.

**Shell layout held.** Full-height rail owning the corner, top bar over the canvas only,
visible dividers between all three regions, rail head matched to the 52px top bar, pinned
brand block with only the nav list scrolling, legible collapsed flyouts, flicker-free
collapse.

**UI states rendered.** Success, loading skeleton, empty no-data, empty no-results and error
with Retry, all four across the mockup. Three deliberate strengthenings: a failed evidence
load counts as **unmet** on both gate screens; "Unverified" is a first-class test outcome
distinct from pass; and "stale" is a third state on go-live evidence.

**Forms.** Every create, edit, multi-step and settings form is page-hosted on its own route
or as a form region on the current page. **No modal carries a form anywhere in this
curation.** Dialogs appear only for a decision that must be answered now — a destructive
confirmation naming its target, a typed confirm word, a rejection reason.

**Lists.** Every list declares its default sort, states which columns sort, names its facets,
runs both sort and filter server-side over the whole result set, reports the filtered total in
both counts, returns to page 1 on any change, and keeps its state in the URL query. Two
default sorts were chosen against the obvious option and the reasoning recorded: Projects
sorts by Updated rather than blocked count, and Enrichment Queue sorts by AI-surface
membership rather than alphabetically.

**Wizards.** The three step-by-step forms specified in 04-UI-Specification each carry exactly
Back and Continue, with Continue validating the step and **saving a resumable server-side
draft before advancing**, becoming Provision, Create or Finish on the last step. No third
"Save as draft" control. No draft holds a credential.

**Role and access.** All four layers applied per screen: cluster and feature gate on both the
sidebar and the server-side handler, per-record policy, list and query scope, and the hard
gate on permanent delete. Unauthorized items absent, not dimmed. Business User is narrowed to
the Assistant, the Business Glossary, read-only project status, and the two surfaces where the
business tier genuinely leads.

**Branding.** The approved palette, type, shape, spacing and elevation applied unmodified in
both themes, with no per-screen colour or font anywhere in this curation. Application name
confirmed by the user; navigation tree and role labels specified for confirmation.
**Missing asset flagged:** the approved brand asset pack and its installed location, with its
impact stated in section 3.

**Authorized deviations.** None. One archetype conflict was named openly and resolved into a
compliant shape rather than taken as an exception, and it is referred back to the technical
lead for a product-wide decision.
