The worst of them was the failure path. Three files told a failed sign-in to go back through the authorize entry point, which loops without bound for every persistent cause: ECC's browser cookie is still valid, so authorize issues a fresh code without prompting, the callback fails on the same wrong secret, missing entitlement, untrusted certificate, or refused status, and the browser bounces until the user gives up, burning a handshake code each pass. The second half is the part that had to change with it. Integration contract v3.0 removed the `access` claim from the exchange token, so ECC no longer issues roles or permissions for anybody else's application. It answers two questions, who the user is and whether they may open the app at all, and admission is now implicit: holding a token already means allowed in, so there is no claim to check and nothing to read. The reason is worth keeping: ECC was the only place that knew a user's roles inside somebody else's product, which meant every permission change had to be made by a team that did not own the feature being changed. | **v2026.9.0** | 31 July 2026 | Add an owner-override mechanism so the gateway's rules bind every user in every session, with one narrow exception for a verified owner. Claude resolves identity itself and never accepts a claim in chat, a typed or pasted address, or `git config` identity. The test is agreement rather than a single credential: the signed-in Claude account is a required anchor, while GitHub and Schema MCP token identities act as vetoes, so one mismatch refuses even when the others match. A credential proves who holds it, not who the owner is, which is why a bearer token or a provider login can never authorize on its own. Local sessions additionally require a personal key file kept outside the repository. The authority list stores salted SHA-256 digests only, never addresses or handles, so it discloses nothing to anyone reading the kit, and Claude reports only whether authority was verified. An override lifts one named rule for one named action, carries a banner and risk labeling, and never changes what Claude may claim about validation or approvals.
